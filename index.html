01 — The hardware

What is an M5⁠Stack⁠Chan?

The starting point is an M5Stack CoreS3 — a palm-sized developer board built around an ESP32-S3, wrapped in the open-source “StackChan” robot form factor: a little servo-driven head with a bright screen for a face. It ships as the AI Desktop Robot Kit (K151-R): two servos for a nod-and-turn neck, a 2-inch touch LCD, a camera, a mic, a speaker and a Li-ion cell.

Out of the box it is charming — and completely dependent on its maker's servers to think, hear and speak. Everything below is about changing that: keeping the body, replacing the brain, and doing it without giving up an inch of privacy.

02 — The story

Open by design, local by choice

Here's what makes this fair game: the robot is open source. It was crowdfunded on Kickstarter and built from the start to be opened up, studied and run however its owner likes — that's the whole point of it. Out of the box it leans on XiaoZhi, the maker's cloud: it thinks with an Alibaba Qwen model, speaks with a cloud voice, and checks in with the maker's servers at boot — a perfectly good default, and entirely optional. So we asked the obvious question — why route the whole household through someone else's cloud when the same robot can run on our own terms? — and moved the brain home.

Ours · on our terms

Kept honest: “local-first” here means no vendor lock-in and no phone-home — not that a data-centre is never touched. The reasoning brain is Claude, running under Sanjay's own Anthropic plan (not a bundled black-box model); speech is transcribed on the Mac with faster-whisper; the spoken voice uses a swappable TTS engine (Microsoft edge-tts, or a fully-local VOICEVOX engine). Every household integration talks to a local device or a keyless public API — never a vendor account.

How the switch happened, in stages

  1. Stage 0

    Stub-mode brain

    A local MCP server with the tool surface built and testable before the box even arrived — every data source returns stub text until wired.

  2. Stage 1

    De-clouding the boot

    A local OTA stub answers the boot-time check the device would otherwise send to xiaozhi.me, so it can come alive without checking in with anyone.

  3. Stage 2

    Bridge proof-of-concept

    An MCP pipe dialled out into the maker's access point to inject local tools — enough to prove the idea. Superseded by the reflash.

  4. Stage 3 · now

    Claude as the brain

    Factory agent replaced with the open stackchan-mcp firmware; the device dials a local gateway; Claude reasons over the tools and drives the robot. Logs read ESP32 ready … tools=40.

  5. Stage 4 · next

    Always-on, off the laptop

    Move the gateway onto an always-on home box so the robot lives independent of any one Mac. Deferred — today's setup already does the job.

03 — How it works

04 — What we customised

Every area, rebuilt

Each capability below was added deliberately, kept narrow, and made to fail honestly — if the robot doesn't know, it says so rather than guessing. Here is each area, in detail.

A

Voice — touch, transcribe, think, speak

Touch the screen and a red dot appears; ask your question; touch again to end. The device streams Opus audio to the gateway, which hands it to the voice loop on the Mac. faster-whisper (the small model, for Hindi support) transcribes it locally; Claude reasons over the tools and answers; the reply is spoken back and the LEDs go dark, ready for the next one.

  • No wake word — by design. Whisper hallucinates sentences from silence, so a touch is the trigger. Explicit beats a robot that answers an empty room.
  • Bilingual. English vs. हिंदी is detected per-utterance against a threshold fitted to real recordings.
  • LED grammar. Dark = ready · blue = listening / thinking / speaking · magenta = the answer is routed to a room speaker instead.

faster-whisperclaude -pedge-tts / VOICEVOXffmpeg · OpusWebSocket

B

Face recognition & identity

The onboard camera lets the robot know who is asking. Enrolment captures a handful of photos and stores a 128-dimension face embedding; on every question it detects the face, computes a vector and matches it by cosine similarity against the enrolled set. Recognition is what makes “email me my report” safe — the recipient is resolved from the recognised person, never dictated aloud.

  • On-device vision models. YuNet detects the face, SFace embeds it — both run on the CPU through OpenCV's DNN module. No cloud vision API.
  • Identity as a gate. Below the match threshold, the robot simply says it isn't sure who you are, and refuses to send anything.
  • Private by construction. Embeddings and email addresses live in a local file that never leaves the Mac and is never committed.

OpenCV DNNYuNetSFace · 128-Dcosine match

C

Documents — even the scanned ones

Point the robot at a folder of documents and ask about them. It keeps a lightweight index (names, paths, dates) so lookups are instant, and only ever reads inside folders you've explicitly allowed. Text PDFs are read directly. The hard case — a photographed lab report with zero extractable text — is detected, rasterised page-by-page at full resolution, with the page rotation read from the PDF stream rather than guessed, then read as an image.

  • Scoped, not root. Searches walk only enrolled document roots — never your whole disk.
  • Honest about limits. “Showing 8 of 12” — it never pretends a truncated list is complete, and never answers about a file it didn't actually open.
  • iCloud-aware. If a file is a placeholder that hasn't downloaded, it fetches it or says it can't — no silent blanks.

pypdfPillow (RAQM)index-first search

D

Email out — with no “to” field

The robot can email you a document it just found. Deliberately, the send tool has no recipient parameter: the address comes from the recognised face, so a misheard name can't send your medical report to a stranger. Delivery is plain Gmail SMTP with a revocable app-specific password kept out of every log.

  • Find first, email second. “Find my last report” stands alone; emailing it is an optional follow-on, never automatic.
  • Attachment scope-checked. Only files from allowed document roots can be attached.

smtplibGmail app-passwordidentity-gated

E

Home automation — lights & sound, all local

Two integrations, both talking straight to devices on the LAN with no manufacturer cloud account. Philips Hue lights are driven over the bridge's local CLIP v2 API (paired once, with a revocable key) — on/off, brightness, colour, temperature. Sonos speakers are found by UPnP and used for room audio: say “play it in the living room” and the answer is streamed to that room instead of the robot's 1 W speaker, with the LEDs turning magenta to show it.

  • No accounts. Hue via local bridge, Sonos via local UPnP — nothing goes through Philips or Sonos servers.
  • Apple Music, catalogue-only. Search returns track IDs; playback goes out to Sonos — no user login.

Hue CLIP v2SoCo · UPnPhttpx

F

Calendar & reminders

The robot reads an iCloud calendar over CalDAV, read-only, with an app-specific password. It looks ~90 days ahead, lets iCloud expand repeating events, and answers from a cache refreshed every few minutes — telling you when the cache is stale rather than pretending it's live. Reminders are separate and set only from the panel, never by voice, because a misheard time is a silent failure.

caldavread-only90-day lookahead

G

The watchers — a household news desk

A family of adapters that keep an eye on the world and fold it into a spoken briefing. They share one rule above all: never invent. A launch with no confirmed time is “some time in October”, not a made-up hour; a news story is quoted from the headline the newsroom wrote, and the newsroom is named — no confident summary that could get a fact about a war wrong, spoken aloud in a house with a 90-year-old in it.

🏏 Sport

Cricket & football scores, wickets, overs and upcoming fixtures from ESPN — live cadence during a match, idle otherwise.

🚀 Space

Launches, the Space Station, eclipses and storms from NORAD, NASA, ESA, JAXA, ISRO — sky events filtered to what's visible locally.

📰 News

17 keyless newsrooms across 7 regions, ranked by cross-region agreement, capped at three stories, headlines quoted verbatim.

✈️ Flights

Live position, gate and status for followed flights — AeroDataBox where keyed, keyless ADS-B, airport weather and US ground delays otherwise.

🌍 Alerts

Earthquakes, cyclones, floods and volcanoes from USGS and NASA EONET for watched cities — alert on threshold, silent when stale.

📈 Markets

Stock closes and threshold alerts via yfinance — reports finished sessions, and never says “today” across a timezone line.

keyless / owned APIscached & stale-awarenever fabricates

H

Discord — the Minecraft watch

A small bot watches a Discord channel and flags matching messages — used to catch the family Minecraft server starting up or crashing. It reads with a proper bot token and the Message Content intent, so bodies actually arrive, and matches them against rules set in the panel.

discord.pymessage-content intent

I

Avatar & expressions

The face on the screen is Claude's, rendered from a template and pushed into the device's PSRAM — which survives a power cycle, so it stays after a reboot until the stock yellow smiley returns as a signal to re-push. Blink, mouth and head position are all driven live as it talks.

PSRAM pushset_blink / set_mouth

J

Servo motion & presence

Two servos give a neck. While thinking or speaking the head makes small active glances; at rest it idles with a random glance every 15–40 seconds — unless the screen is dimmed or it's night. How much it moves (Never / While awake / Always) is a panel setting that takes effect on the next glance, no restart.

yaw + pitchidle wandernight-aware

K

The control panel

Everything above is configured from one local Flask web app — 15+ tabs for devices, people, documents, each watcher, night hours, motion and volume, plus a read-only troubleshooting tab with a dozen diagnostics. It runs detached, so it survives closing the terminal, and it's the only place identity-sensitive things (faces, email addresses, reminders) can be set.

05 — Under the hood

The stack, top to bottom

On the device

  • ESP32-S3 firmware — open stackchan-mcp v1.16.0
  • Opus audio over WebSocket
  • NVS-stored local gateway URL + token (mDNS off)
  • Factory image backed up before flashing

The brain & voice

  • Claude, driven over MCP (claude -p)
  • faster-whisper — local speech-to-text
  • edge-tts / VOICEVOX — swappable TTS
  • OpenCV DNN — YuNet + SFace for faces

The server

  • Python MCP server — mcp, plain & debuggable
  • httpx, websockets, python-dotenv
  • pypdf + Pillow (RAQM) for documents
  • Adapter-per-source; stub mode when unconfigured

Integrations

  • caldav · Gmail SMTP · SoCo (Sonos)
  • Hue CLIP v2 · discord.py · yfinance
  • ESPN · NORAD/NASA · ADS-B · USGS/EONET · RSS
  • Every secret in a gitignored .env

A deliberate constraint: plain, debuggable Python — no heavy agent frameworks. Every data source is a small adapter that falls back to stub text when it isn't configured, so the whole thing was testable before the hardware ever arrived, and any one piece can break without taking the rest down.

In progress

Deferred

  • Home Assistant bridge (stub in place)
  • OneDrive digest ingestion

  • Custom device-driving firmware
Known limitations — kept in plain sight
  • 1 W speaker is quiet across a kitchen — a Grove Bluetooth speaker is the planned fix.
  • Two servos mean limited expressiveness — a deliberate trade against a bulkier multi-servo robot.
  • mDNS is off in this firmware, so the gateway IP is pinned; moving Macs means repointing the device.
  • Whisper's small model takes ~2–3 s to warm up on the first question, then is near-instant.
  • No wake word — a touch is required. A feature, not a gap: it kills false triggers.
